**5. "Start Practice" Button Logic (Word Bank Card)**

*   **Goal:** Make the "Practice" button on a specific word bank card initiate a practice session for *only that bank*, potentially with options.
*   **Backend:**
    *   **File:** `src/server/api/routers/vocab.ts`
    *   **Tasks:**
        *   [ ] Modify `startVocabSession` mutation:
            *   Change `wordBankIds: z.array(z.string())` to `wordBankId: z.string()` (since it's now for one bank).
            *   *Optional:* Add optional input fields for practice parameters (e.g., `durationMinutes: z.number().optional()`, `wordLimit: z.number().optional()`).
        *   [ ] Modify `getNextVocabWord` query:
            *   It needs to know which bank(s) the session is for. Add `wordBankId` (or `wordBankIds` if supporting multi-select later) to the `PracticeSession` model or pass it as input to `getNextVocabWord`. Let's add `wordBankId` to `PracticeSession` for simplicity now.
            *   Update Prisma schema for `PracticeSession` to include `wordBankId String?` (and potentially a relation). Run migration.
            *   Update `startVocabSession` to save the `wordBankId`.
            *   Update the `where` clause in `getNextVocabWord` to filter by `wordBankId: session.wordBankId` instead of checking ownership via `wordBank.userId`.
*   **Frontend:**
    *   **File:** `WordBankCard` component (from Step 4)
    *   **Tasks:**
        *   [ ] Change the "Practice" button from a `Link` to a regular `Button` with an `onClick` handler.
        *   [ ] Create a `useMutation` hook for `api.vocab.startVocabSession`.
        *   [ ] In the `onClick` handler, call the mutation, passing the specific `bank.id` as `wordBankId`.
        *   [ ] Handle loading state for the button.
        *   [ ] On mutation success, use the router to navigate to `/vocabulary/practice/[sessionId]`.
        *   [ ] *Optional:* Implement a modal triggered by the button to ask for practice options (time, word count) before calling the mutation. (Defer this for now).
