# Word Management System Specifications

## 1. Word Storage Requirements

### Database Schema Changes
1.  **WordMaster Table** (Master word list)
    *   `id`: Unique identifier
    *   `baseWord`: Base English word (e.g., "run")
    *   `variations`: JSON array of word forms (e.g., ["ran", "running"])
    *   `language`: Language code (default "en")
    *   `wordType`: noun/verb/adjective/etc.
    *   `definition`: Dictionary definition
    *   `sampleSentences`: JSON object with grade-level sentences
        ```json
        {
          "default": "Default sentence.",
          "grade1": "I like to run fast.",
          "grade2": "She runs every morning."
        }
        ```
    *   `translations`: JSON object with translations by language
        ```json
        {
          "default": "Default translation",
          "zh": {
            "word": "跑",
            "sentences": {
              "default": "默认翻译句子。",
              "grade1": "我喜欢快跑。"
            }
          }
        }
        ```
    *   `isDictionaryWord`: Boolean flag for dictionary words
    *   `createdAt`/`updatedAt`: Timestamps

2.  **Word Table** (User's instance of a word in a bank)
    *   `id`: Unique identifier
    *   `wordMasterId`: Foreign key to `WordMaster`
    *   `wordBankId`: Foreign key to `WordBank`
    *   `text`: Temporary field for backward compatibility (will be removed).
    *   `interval`, `easeFactor`, `repetitions`, `nextReviewDate`: SRS fields
    *   `isStarred`: Boolean for user starring
    *   `notes`: User-specific notes for this word in this bank
    *   `createdAt`/`updatedAt`: Timestamps (Implicitly available)

3.  **WordBank Table**
    *   Keeps direct relation to `Word` model (deviation from original JSON spec for simplicity for now).

### Word Processing Flow (Target Logic for `addBatch`)
1.  When user uploads words:
    *   For each `wordText` in the input:
        a.  **Check Existence:** Query `WordMaster` where `baseWord` matches `wordText` OR `variations` array contains `wordText` (using raw SQL `@>` operator).
        b.  **If Exists:** Use the existing `wordMasterId`.
        c.  **If Not Exists:**
            i.  **Dictionary Check:** Call external API/service to check if `wordText` is a valid dictionary word.
            ii. **Enrichment (if Dictionary Word):**
                *   Call `enrichWord` (Gemini API) to get `wordType`, `definition`, default `sampleSentence`, default `translation`.
                *   *(Future)* Generate variations (requires separate AI call/logic).
                *   *(Future)* Generate grade-level sentences (requires separate AI call/logic).
                *   *(Future)* Generate translations for other languages based on user prefs (requires separate AI call/logic).
            iii. **Create WordMaster:**
                *   If dictionary word & enrichment succeeded: Create `WordMaster` with `baseWord`, `variations` (initially just `[wordText]`), `wordType`, `definition`, `sampleSentences` (JSON with `default`), `translations` (JSON with `default`), `isDictionaryWord: true`.
                *   If dictionary word & enrichment failed: Create `WordMaster` with `baseWord`, `variations`, `isDictionaryWord: true`, and null/empty defaults for other fields. Log the enrichment error.
                *   If not dictionary word: Create `WordMaster` with `baseWord`, `variations`, `isDictionaryWord: false`, and null/empty defaults for other fields.
            iv. Use the newly created `wordMasterId`.
        d.  **Create Word Record:** Create a `Word` record linking the `wordMasterId` and `wordBankId`, including the temporary `text` field (using `wordText`). Use `skipDuplicates` to avoid errors if the same master word is added twice in one batch for the same bank.
