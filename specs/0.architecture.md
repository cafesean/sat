# System Architecture Plan - SAT Study App

This document outlines the high-level architecture and development plan, broken down into sprints, based on the initial requirements.

## Core Technologies

*   **Framework:** Next.js (App Router)
*   **Language:** TypeScript
*   **Styling:** Tailwind CSS
*   **UI Components:** Shadcn UI, Radix UI
*   **Database ORM:** Prisma
*   **API Layer:** tRPC
*   **Authentication:** NextAuth.js (or similar like Clerk)
*   **AI Integration:** Google Gemini API
*   **State Management:** Zustand (for global state if needed, primarily rely on tRPC/React Query for server state)
*   **Database:** PostgreSQL (Recommended, flexible)

## Sprint Breakdown

### Sprint 1: Foundation & Core Setup

*   **Goal:** Establish the project structure, core dependencies, basic layout, authentication, and database connection.
*   **Tasks:**
    *   [X] Initialize Next.js project with TypeScript, Tailwind CSS. *(Partially completed)*
    *   [ ] Integrate Shadcn UI.
    *   [ ] Set up basic project structure (`src/app`, `src/components`, `src/lib`, etc.).
    *   [ ] Implement Root Layout (`src/app/layout.tsx`) with ThemeProvider.
    *   [ ] Implement basic Navbar and Sidebar components.
    *   [ ] Choose and set up Database (e.g., PostgreSQL).
    *   [ ] Integrate Prisma ORM, define initial schema stubs.
    *   [ ] Set up Authentication (e.g., NextAuth.js with a provider like Google/Email).
    *   [ ] Set up tRPC for API communication.
    *   [ ] Configure Environment Variables (`.env`).

### Sprint 2: Vocabulary Module - Core Features

*   **Goal:** Implement the ability to create word banks and add words, including AI enrichment.
*   **Tasks:**
    *   [ ] Define Prisma Schema for `WordBank`, `Word`.
    *   [ ] Create tRPC routers/procedures for WordBank CRUD (Create, Read, Update, Delete).
    *   [ ] Create tRPC routers/procedures for adding Words to a bank.
    *   [ ] Develop UI for listing and creating/editing Word Banks.
    *   [ ] Develop UI for adding words (textarea input, parsing logic).
    *   [ ] Create a backend service/tRPC procedure to interact with the Gemini API.
    *   [ ] Implement logic to call Gemini API upon word addition for definitions, sample sentences, and translations.
    *   [ ] Implement logic to save enriched word data to the database via Prisma.

### Sprint 3: Vocabulary Module - Practice

*   **Goal:** Implement the vocabulary practice feature using spaced repetition and AI grading.
*   **Tasks:**
    *   [ ] Define Prisma Schema for `PracticeSession` (Vocab), `WordPracticeLog`. Include fields for spaced repetition (e.g., interval, ease factor, next review date).
    *   [ ] Implement core Spaced Repetition System (SRS) logic (e.g., SM-2 algorithm adaptation) in `src/lib`.
    *   [ ] Create tRPC procedures to fetch words for a practice session based on SRS logic.
    *   [ ] Develop UI for the vocabulary practice session (display word, prompt for sentence).
    *   [ ] Integrate Gemini API call for grading the user's sentence.
    *   [ ] Create tRPC procedure to record practice results and update word's SRS metadata.
    *   [ ] Implement UI feedback based on AI grading (correct/incorrect, explanation).
    *   [ ] Add UI to select which word banks to include in a practice session.

### Sprint 4: Reading & Writing Module - Practice Setup & Generation

*   **Goal:** Set up the Reading & Writing practice module, including AI question generation.
*   **Tasks:**
    *   [ ] Define Prisma Schema for `PracticeSession` (R&W), `Passage`, `Question`, `AnswerAttempt`.
    *   [ ] Create a backend service/tRPC procedure to generate SAT-style passages, questions, and multiple-choice answers using the Gemini API based on a selected difficulty level.
    *   [ ] Develop UI for starting a Reading & Writing practice session (including difficulty selection).
    *   [ ] Implement logic to trigger AI generation and store the generated content (passage, questions, answers) in the database.
    *   [ ] Create tRPC procedures to fetch a generated practice set.

### Sprint 5: Reading & Writing Module - Practice Execution & Review

*   **Goal:** Implement the R&W practice interface, scoring, and history.
*   **Tasks:**
    *   [ ] Develop UI to display passages, questions, and multiple-choice options.
    *   [ ] Implement logic for submitting answers.
    *   [ ] Create tRPC procedure to record answers and check correctness.
    *   [ ] Implement UI to display immediate feedback (correct/incorrect, correct answer, explanation retrieved from stored data or potentially generated).
    *   [ ] Implement real-time score tally display during the session.
    *   [ ] Develop UI to view past Reading & Writing practice sessions and results (Practice History).
    *   [ ] Create tRPC procedures to fetch practice history.

### Sprint 6: Dashboard, Refinement & Polish

*   **Goal:** Create a user dashboard, refine the UI/UX, improve mobile responsiveness, and prepare for potential deployment.
*   **Tasks:**
    *   [ ] Design and implement a user Dashboard page (`src/app/dashboard/page.tsx`) summarizing progress (e.g., word mastery, recent practice scores).
    *   [ ] Create tRPC procedures to fetch data for the dashboard.
    *   [ ] Conduct thorough UI/UX review and refinement across the application.
    *   [ ] Ensure consistent mobile-first responsiveness.
    *   [ ] Add necessary loading states and error handling.
    *   [ ] Implement basic unit/integration tests for critical logic (SRS, API interactions).
    *   [ ] Prepare deployment configuration (e.g., Vercel).
