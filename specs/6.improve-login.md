# Spec: Add Email/Password Authentication

This document outlines the steps required to add traditional email and password authentication to the existing NextAuth.js setup, complementing the current email magic link method.

## 1. Database Schema (`prisma/schema.prisma`)

*   **Modify `User` Model:**
    *   Add a new field: `hashedPassword String?`
    *   Ensure the `email` field is non-nullable and unique: `email String @unique` (verify it's not nullable).

## 2. Dependencies

*   Install `bcryptjs` and its types:
    ```bash
    pnpm add bcryptjs
    pnpm add -D @types/bcryptjs
    ```

## 3. NextAuth.js Configuration (`src/lib/auth/options.ts`)

*   **Import necessary modules:**
    *   `CredentialsProvider` from `next-auth/providers/credentials`
    *   `bcryptjs`
    *   `prisma` client from `@/lib/db/prisma`
*   **Add `CredentialsProvider` to `providers` array:**
    ```typescript
    CredentialsProvider({
      name: 'Credentials',
      credentials: {
        email: { label: "Email", type: "email", placeholder: "jsmith@example.com" },
        password: { label: "Password", type: "password" }
      },
      async authorize(credentials) {
        if (!credentials?.email || !credentials?.password) {
          console.log('Missing credentials');
          return null;
        }

        const user = await prisma.user.findUnique({
          where: { email: credentials.email },
        });

        if (!user || !user.hashedPassword) {
          // User not found or doesn't have a password set (maybe magic link only)
          console.log('User not found or no password set for:', credentials.email);
          return null;
        }

        const isValidPassword = await bcrypt.compare(
          credentials.password,
          user.hashedPassword
        );

        if (!isValidPassword) {
          console.log('Invalid password attempt for:', credentials.email);
          return null;
        }

        console.log('Credentials valid for:', credentials.email);
        // Return user object without password
        // eslint-disable-next-line @typescript-eslint/no-unused-vars
        const { hashedPassword, ...userWithoutPassword } = user;
        return userWithoutPassword;
      }
    })
    ```

## 4. Registration Logic (tRPC)

*   **Create Router:** `src/server/api/routers/auth.ts` (if not exists) and add it to the root router.
*   **Define Zod Schema:** For registration input (`email`, `password`, `name?`). Include password complexity validation (e.g., `min(8)`).
*   **Create `register` Mutation:**
    *   Use `publicProcedure`.
    *   Input: Zod schema defined above.
    *   Logic:
        1.  Check if user exists (`prisma.user.findUnique`).
        2.  If user exists and `hashedPassword` is set, throw `TRPCError` (CONFLICT).
        3.  Hash the input `password` using `bcrypt.hash(password, 10)`. (Adjust salt rounds as needed).
        4.  If user exists but no password (`hashedPassword` is null), `prisma.user.update` the record with the `hashedPassword`.
        5.  If user does not exist, `prisma.user.create` a new user with `email`, `hashedPassword`, `name`.
        6.  Return `{ success: true }`.

## 5. UI Implementation

*   **Login Component/Page:**
    *   Add input fields for `email` and `password` (`type="password"`).
    *   Add a submit button.
    *   On submit, call `signIn('credentials', { redirect: false, email, password })`.
    *   Handle the returned promise: show error messages (e.g., "Invalid email or password") using Toasts on failure, redirect on success.
    *   Ensure the magic link option remains visible and functional.
    *   Add a link to the Sign Up page.
*   **Sign Up Component/Page (`/signup`):**
    *   Create a new route and component.
    *   Add input fields for `email`, `password`, `confirmPassword`, `name` (optional).
    *   Implement client-side validation (passwords match, minimum length).
    *   On submit, call the `auth.register` tRPC mutation.
    *   Display loading states.
    *   Show success/error feedback using Toasts.
    *   Redirect to login page or dashboard on successful registration.

## 6. Database Migration

*   Run the migration after updating the schema:
    ```bash
    pnpm prisma migrate dev --name add-user-password
    ```

## 7. Security Considerations

*   Use `type="password"` for password inputs.
*   Enforce password complexity (client-side for UX, server-side via Zod for security).
*   **Recommended:** Implement rate limiting on login and registration endpoints in production.
*   Ensure HTTPS is enforced.

## 8. Optional Enhancements (Future Sprints)

*   Password Reset Functionality.
*   "Social" Logins (Google, etc.) - already planned/partially implemented.
*   Two-Factor Authentication (2FA).
