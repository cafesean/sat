# Framework Development Plan - SAT Study App

This document serves as a living framework wiki for the SAT Study App, detailing the architectural goals, guiding principles, and integration strategies for core components like tRPC, Prisma, and the Gemini API.

## Overview

The SAT Study App is designed with a modular architecture aimed at enhancing performance, scalability, and reusability. Our approach is AI-first, leveraging advanced technologies to provide a seamless learning experience. The architecture is driven by sprint goals that emphasize modularity, allowing teams to work independently while ensuring that components integrate smoothly. Key integration points include the Gemini API for AI-driven features, tRPC for type-safe API communication, and a Spaced Repetition System (SRS) for optimizing learning.

## Key Concepts

- **SRS (Spaced Repetition System):** A learning technique that schedules reviews of material at increasing intervals to enhance retention.
- **Client/Server State Separation:** A design principle that distinguishes between client-side data (UI state) and server-side data (persistent state), ensuring clear boundaries and efficient data management.
- **Gemini API Integration Strategy:** A systematic approach to interfacing with the Gemini API, focusing on error handling, request formatting, and data retrieval.
- **tRPC Middleware:** Reusable logic that can be applied to tRPC procedures for tasks such as authentication and input validation, ensuring a consistent approach across the application.
- **Prisma Data Flows:** The pathways through which data is managed and manipulated in the database, leveraging Prisma for seamless interactions.

## Common Pitfalls

- **Misusing Zustand for server state:** Ensure that Zustand is used for client state management, not server state, to avoid data inconsistency.
- **Skipping input validation with Zod:** Always validate inputs to prevent unexpected data issues and enhance security.
- **Not indexing DB fields used in filters/sorts:** Proper indexing is crucial for performance; neglecting this can lead to slow queries.
- **Tightly coupling Gemini AI responses to logic:** Use fallback-safe patterns to ensure that the application remains robust even if the AI responses are suboptimal.
- **Missing auth checks in tRPC procedures:** Always implement authentication checks to protect sensitive endpoints.
- **Not cleaning up stale client cache after mutations:** Regularly clear or update the client cache to prevent outdated data from persisting.

## Project Structure (Reference)

The project structure remains as follows:

```
src/
├── app/                  # Next.js App Router (Pages & Layouts)
├── components/           # Shared React Components (UI & Feature)
│   ├── ui/               # Shadcn UI Components
│   └── features/         # Feature-specific components (e.g., vocab, reading)
├── lib/                  # Core logic, utilities, external API clients
│   ├── api/              # Gemini API client wrapper
│   ├── auth/             # Authentication configuration (NextAuth.js)
│   ├── db/               # Prisma client instance and setup
│   ├── srs/              # Spaced Repetition System logic
│   ├── trpc/             # tRPC client setup
│   └── utils.ts          # General utility functions (e.g., cn for Tailwind)
├── schemas/              # Zod schemas for validation (tRPC inputs, forms)
├── server/               # Backend-specific code (tRPC routers, context)
│   ├── api/              # tRPC Routers
│   │   ├── root.ts       # Root tRPC router merging sub-routers
│   │   ├── routers/      # Sub-routers per feature (e.g., vocab.ts, reading.ts, user.ts)
│   │   └── trpc.ts       # tRPC procedure builders, middleware (e.g., auth)
│   └── db/               # Prisma schema (schema.prisma)
├── styles/               # Global CSS
├── types/                # TypeScript type definitions
└── env.mjs               # Environment variable validation (using T3 Env)
```

## Database Setup (Reference)

The database is set up using PostgreSQL with Prisma as the ORM. The schema follows a snake_case convention for table and field names, ensuring consistency and adherence to best practices.

## tRPC Layer (Reference)

tRPC provides type-safe communication between the frontend and backend. It is essential for defining API endpoints and grouping related procedures. Middleware can be applied for reusable logic, such as authentication checks.

## Authentication (Reference)

NextAuth.js manages user login, registration, and session management, providing a robust solution for handling user authentication within the app.

## Environment Variables (Reference)

Management of environment variables is crucial for both local development and deployment. The application utilizes T3 Env for validation, ensuring that necessary variables are correctly configured.

## Usage

- **Extending tRPC Routers:** Tech leads can extend tRPC routers by defining new procedures and integrating them into existing routers.
- **Working with Prisma + Zod + tRPC:** Developers should use Prisma for data management, Zod for input validation, and tRPC for API communication to create a cohesive development experience.
- **Testing Endpoints:** QA can test endpoints using tools like Postman or by utilizing generated test data to ensure that all functionalities work as intended.

This document serves as a comprehensive guide for developers, tech leads, and QA teams, providing insights into the architectural framework and best practices for the SAT Study App.
